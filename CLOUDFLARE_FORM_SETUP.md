# Серверная форма АМАПС через Cloudflare Worker

## Зачем
GitHub Pages остаётся хостингом сайта. Cloudflare Worker принимает форму и отправляет письмо через Resend. Секретный ключ не попадает в браузер.

## Рекомендуемый адрес
forms.amaps-pro.ru

## Переменные Worker
- RESEND_API_KEY — секрет
- AMAPS_TO_EMAIL — info@amaps-pro.ru
- AMAPS_FROM_EMAIL — АМАПС <info@amaps-pro.ru>

## Развёртывание через панель Cloudflare
1. Workers & Pages → Create application → Worker.
2. Вставить содержимое cloudflare-worker.js и Deploy.
3. Settings → Variables and Secrets → Add:
   - RESEND_API_KEY как Secret.
   - AMAPS_TO_EMAIL как Variable.
   - AMAPS_FROM_EMAIL как Variable.
4. Settings → Domains & Routes → Add → Custom Domain.
5. Указать forms.amaps-pro.ru.
6. После публикации проверить POST-запрос и затем указать https://forms.amaps-pro.ru в meta amaps-form-endpoint в index.html.

## Важно
Не добавлять реальный RESEND_API_KEY в GitHub.

## Контроль результата обработки

- В новой версии формы для каждой попытки создаётся уникальный номер обращения, который сохраняется при сетевом повторе неизменённой заявки и меняется после правки формы.
- Номер обращения включается в письмо; почтовому сервису передаётся ключ предотвращения повторной отправки. Сервис хранит ключ только ограниченное время (24 часа), поэтому это защита от быстрых повторов, а не постоянное хранилище заявок.
- Успешный ответ означает **принятие письма сервисом отправки**, а не доказанную доставку в корпоративный ящик и не регистрацию в СРМ. Форма больше не сообщает, что АМАПС уже получил заявку.
- **До полной приёмки по COM-066/067** требуется отдельное защищённое постоянное хранилище исходного обращения, повторные попытки после ошибок, автоматическая запись в Attio, обратное чтение, антиспам, журнал доставки и проверка обеих категорий заявок. Текущая версия этих возможностей ещё не предоставляет.
- Изменения в этой ветке **не развёрнуты на действующем сайте**. Для публикации требуются проверка синтаксиса и испытания на отдельной площадке с тестовыми обращениями; не выдавать отдельный удачный запрос за успешную сквозную регистрацию.
