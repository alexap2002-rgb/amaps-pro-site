# АМАПС: строгий договорный запрет исходящей отправки

## Условия
Этот обработчик **не развёрнут**. Он отправляет только заранее письменно согласованный текст (без вложений), который находится в закрытой базе `OUTBOUND_DB`. В запросе разрешён только номер утверждённого письма. Добавить новый текст, получателя, ссылку, ТЗ, цену или вложение в запрос невозможно.

Для отправки требуется одновременно:
- Подтверждённое наличие **основного подписанного договора** данного исполнителя.
- **Другой подписанный документ**, который защищает именно эту возможность.
- Точные совпадения заявки, исполнителя и адреса получателя с обеими записями.
- Отсутствие отзыва защиты и действующий срок.
- Ручное утверждение окончательного письма, неизменность его текста по контрольной сумме SHA-256.
- Отдельный секрет `OUTBOUND_TOKEN`, доступный только доверенному каналу; прочие автоматизации не должны иметь прямого доступа к Resend.

Подтверждение подписания **не выводится из отметки «ДА» отправителя**. Доказательства и контрольные суммы заносятся в `supplier_deal_protection` только доверенным оператором после сверки исходных документов. Для утверждения конкретного текста создаётся запись `approved_outbound_messages`; других путей отправки этот сервис не предоставляет.

## Включение
1. Подготовить независимую закрытую базу D1, применить `migrations/0002_outbound_protection.sql`, настроить Worker `cloudflare-outbound-guard.js`.
2. Секреты `OUTBOUND_TOKEN`, `RESEND_API_KEY` хранить только в секретах окружения Cloudflare. Ключ почтового сервиса ограничить по назначению.
3. Проверить запрет: нет договора, одинаковые документы, просрочена защита, другой исполнитель, изменённый текст, попытка вложения, повтор, сбой почты. Выполнить положительный тест только на тестовом адресе с вымышленной заявкой и заранее утверждённым текстом.
4. После развёртывания перекрыть технические обходные пути: старые ключи прямой отправки и независимые почтовые интеграции. Пока это не сделано, **абсолютного запрета на всю почту нет**. Разведка никогда не отправляет письма самостоятельно.
5. Для отправки рабочих ТЗ с вложениями потребуется отдельный контролируемый процесс: подписанные документы и контрольные суммы каждого вложения, безопасное сканирование файлов и финальная проверка. Сейчас вложения **запрещены технически**.

## Что не означает статус
Статус `sent` означает принятие почтовым сервисом, а не подтверждённую доставку. Для фактической доставки нужны подтверждённые уведомления почтового сервиса. Наличие записи в базах само по себе не удостоверяет юридическую силу подписей; оригиналы и полномочия подписантов проверяются отдельно.

**До развёртывания и закрытия прямых каналов отправки действует абсолютное операционное правило:** ни одному потенциальному исполнителю нельзя отправлять сведения конкретной сделки без проверенного основного подписанного договора и отдельной подписанной защиты этой сделки.
