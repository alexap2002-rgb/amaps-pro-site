# АМАПС: внедрение защищённого приёма с сайта
Это **проект изменения**, а не сообщение о развёртывании. Текущий рабочий обработчик не менять до полного испытания.

## Порядок включения в Cloudflare
1. Сделать резервную копию действующего обработчика и его переменных; подтвердить, какой Worker действительно развёрнут для https://amaps-form.alexap2002.workers.dev/.
2. Создать закрытую базу Cloudflare D1 (`LEADS_DB`) и применить `migrations/0001_site_submissions.sql`. Настроить закрытое хранилище R2 (`LEADS_FILES`); не открывать публичный доступ.
3. Создать проверку Cloudflare Turnstile для доменов amaps-pro.ru и www.amaps-pro.ru. Подключить публичный ключ в `index.html` (мета `amaps-turnstile-sitekey`); секрет добавить в окружение Worker как `TURNSTILE_SECRET` **не в GitHub**.
4. Добавить секрет `RESEND_API_KEY` с минимальными правами и проверить адрес `AMAPS_FROM_EMAIL`; конечный служебный ящик задаётся `AMAPS_TO_EMAIL` (обычно info@amaps-pro.ru). Никогда не размещать ключи и персональные данные в исходном коде.
5. Создать новый Worker или тестовое окружение с кодом `cloudflare-worker-v2.js`, с привязками D1/R2 и плановой задачей 15 минут. Сначала испытать в закрытом окружении без настоящих коммерческих заявок.
6. Испытать: заказчик; исполнитель; отсутствие обязательных данных; повтор того же номера; сбой D1; сбой R2; сбой почты и успешная повторная доставка; вложение 4 МБ; непрошедшая Turnstile; аварийное восстановление из D1; наличие записи в служебной почте. Только после этого переключить действующий адрес Worker/форму, повторить проверку через реальный домен.
7. Сверять журнал D1 с сообщениями на почте и Attio **после квалификации**. Обращение исполнителя — партнёр, а не сделка. Обращение заказчика — предварительная возможность только после проверки спроса. Создание карточки Attio на каждый необработанный веб-запрос в этом изменении **не реализовано**: пока требуется отдельный контролируемый обработчик очереди.
8. Отдельно внедрить защищённый узел **исходящей** отправки. Этот Worker принимает только входящие заявки; он не разрешает раскрытие коммерческой возможности. Без подписанного рамочного договора и отдельной подписанной защиты конкретной сделки запрещено передавать потенциальным исполнителям какие-либо детали, в том числе обезличенное ТЗ.

## Ограничения
- Получение ответа от Resend об отправке означает **принятие письма к доставке**, а не доказанную доставку в ящик. Доставку нужно контролировать событиями Resend.
- Приём через сайт и сохранение в D1 не равнозначны завершённой регистрации в Attio. Нужна сверка и маршрут обработки очереди.
- Проверка MIME/расширения файла не заменяет антивирусную проверку и безопасную обработку вложений.
- Данные содержат контакты. Оценить применимость законодательства о персональных данных, включая размещение у зарубежных поставщиков, трансграничную передачу и локализацию, с профильным юристом до переключения.
- Для ручных писем через почту прямой технической блокировки здесь пока нет. Автоматические письма о конкретных сделках запрещены.
