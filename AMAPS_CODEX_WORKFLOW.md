# Передача заданий между ChatGPT и Codex через GitHub

Управляющий ассистент формулирует ТЗ и критерии приёмки. Владелец репозитория публикует разрешённый к раскрытию текст и передаёт Codex номер Issue или идентификатор ветки. Codex получает текст из GitHub, выполняет работу и возвращает коммит и результаты испытаний через отдельную ветку и черновик pull request. Слияние выполняет владелец после проверки.

Репозиторий публичный. В ТЗ, коммиты, pull requests и логи добавляйте только материалы, разрешённые к публикации. Для испытаний используйте синтетические данные.

## Передача ТЗ

Используйте один из двух входов.

| Канал | Как передать | Как прочитать в checkout |
| --- | --- | --- |
| Ветка Git | Создайте ветку `amaps/tz-ИД` от `main` и сохраните ТЗ в `.github/amaps-task.md`. Пример идентификатора `proverka-formy`. | `python3 automation/amaps_task.py --git proverka-formy` |
| GitHub Issue | Создайте открытое Issue и передайте его номер. После слияния в `main` можно использовать шаблон «Техническое задание для Codex». | `python3 automation/amaps_task.py --issue 17` |

Загрузчик читает ветку из `alexap2002-rgb/amaps-pro-site` по HTTPS и выводит её имя, точный SHA и текст одного файла в UTF-8 размером до 16 КиБ. Загрузка сохраняет текущую ветку. Чтобы проверить заранее согласованную версию, добавьте `--expect-sha` и полный SHA. Для Issue требуется GitHub CLI с действующим входом и доступом к `api.github.com`. На момент настройки доступ к этому домену из Codex Cloud заблокирован, поэтому здесь используйте ветку Git. В среде с доступом к API загрузчик выводит URL, автора, заголовок и текст открытого Issue.

Управляющий ассистент может подготовить для Codex такое сообщение:

> Возьми ТЗ `proverka-formy` из `amaps/tz-proverka-formy` в репозитории `alexap2002-rgb/amaps-pro-site`. Получи его через `python3 automation/amaps_task.py --git proverka-formy`, укажи SHA источника и выполни согласованные критерии. Верни изменения и испытания в отдельной ветке для проверки.

Если используется Issue, замените команду на `--issue <номер>` и укажите его URL в отчёте. Запускайте работу по заданию, которое явно выбрал ответственный за репозиторий. Текст Issue и вложенные ссылки могут содержать посторонние инструкции. Сопоставьте их с согласованными критериями и полномочиями до выполнения, особенно перед запуском стороннего кода, сетевыми запросами и публикацией.

## Испытания и возврат результата

1. От актуальной `main` создайте ветку `codex/amaps-ИД`. Если помощник чтения ещё на проверке, используйте его из ветки интеграции.
2. Внесите изменения по ТЗ и выполните проверки из корня репозитория. Добавьте предметные испытания из критериев приёмки.

   ```bash
   PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s automation -p test_amaps_task.py
   PYTHONOPTIMIZE=0 python3 automation/amaps_public_monitor.py --self-test
   node --check cloudflare-worker.js
   node --check api/lead.js
   python3 automation/check_amaps_site.py
   ```

3. Просмотрите diff и содержимое публикуемого отчёта. Отправьте проверенную ветку `codex/amaps-ИД` и откройте черновик PR в `main`. Когда API недоступен в Codex Cloud, используйте страницу сравнения веток в интерфейсе GitHub.
4. В PR укажите источник ТЗ (URL Issue или ветка и SHA), ссылку на коммит, изменённое поведение, команды с фактическими результатами и оставшиеся ограничения. Для Issue добавьте ссылку вида `Refs #17`. Управляющий ассистент получает ссылку на PR или ветку и сверяет результат с критериями.

Workflow «Проверки проекта АМАПС» выполняет эти проверки на GitHub при отправке веток `codex/amaps-*` и в PR к `main`. Он использует стандартный Linux-раннер публичного репозитория и разрешение `contents: read`. Самопроверка мониторинга работает офлайн. Проверка сайта использует локальный HTTP-сервер. Для получения результата испытаний откройте вкладку Checks в PR или историю запусков GitHub Actions.

## Где возможен автоматический запуск

- **Codex Cloud с ChatGPT Plus.** Задание можно запустить в подключённой облачной среде через интерфейс ChatGPT. Чтение уже выбранного ТЗ и проверки автоматизированы. Возможность запуска из обычного GitHub Issue по `@codex` не подтверждена. Документированное упоминание относится к ревью pull request. [Документация ревью](https://developers.openai.com/codex/cloud/code-review)
- **Codex CLI на доверенной машине.** `codex exec` поддерживает неинтерактивную работу и вход с подпиской ChatGPT. Экспериментальная команда `codex cloud exec --env ENV_ID` позволяет отправить задачу в подключённую среду с той же авторизацией. Для запуска по расписанию нужна доступная доверенная машина с входом в ChatGPT. Для Issues ей также нужен доступ к GitHub API. Перед такой автоматизацией ограничьте очередь заданиями, одобренными владельцем, и оставьте публикацию на отдельном шаге после просмотра diff. [Codex CLI](https://github.com/openai/codex#using-codex-with-your-chatgpt-plan) · [Облачная команда](https://github.com/openai/codex/blob/main/codex-rs/cloud-tasks/src/cli.rs)
- **GitHub Actions.** События Issues могут запустить workflow GitHub. Официальный `openai/codex-action` требует ключ OpenAI Responses API, поэтому для выбранной схемы GitHub Actions выполняет только испытания. Запуск модели использует доступный лимит ChatGPT Plus. [События GitHub Actions](https://docs.github.com/actions/reference/workflows-and-actions/events-that-trigger-workflows#issues) · [Требования Codex Action](https://github.com/openai/codex-action#readme)
